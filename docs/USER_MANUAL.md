# MYBRAIN 사용설명서

병원장 전용 AI 경영 관제탑, myBrain을 쓰는 원장님을 위한 안내서입니다.

이 문서는 코드나 기술 이야기가 아니라 **원장님이 매일 앱을 어떻게 열어
어떤 정보를 보고 어떤 결정을 내리는지**를 담습니다. 처음 여시는 원장님도
90초 만에 첫 화면을 이해할 수 있게 · 이미 쓰시는 원장님도 놓친 기능을
찾을 수 있게 정리했습니다.

# 1부. 시작하기

## 1장. 마이브레인이란

마이브레인(myBrain)은 **치과 병원장 전용 AI 경영 관제탑**입니다.

일반적인 병원 경영 도구가 하지 않는 세 가지를 합쳤습니다:

1. **HR + 재무 + 환자 관계를 한 화면에** — 실장, 회계사, 컨설턴트에게
   각각 물어봐야 알 수 있었던 정보를 하나의 대시보드에 모았습니다.

2. **판정 + 처방까지** — "노쇼율이 8.7%다"에서 끝나지 않습니다. 이
   숫자가 정상인지 · 왜 이 상태인지 · 오늘·이번 주·이번 달 무엇을 해야
   하는지까지 하나의 카드에 담겨 있습니다.

3. **원장님의 언어로** — 회계·경영 전문 용어를 억지로 외우실 필요가
   없습니다. 모든 분석에 **쉬운말 풀이**가 붙어 있고, 어려운 약어는
   도움말에서 언제든 확인하실 수 있습니다.

### 이 앱이 도와드리는 것

- 오늘 새고 있는 돈이 어디인지 3초에 파악
- 이번 주 실장님과 논의할 안건 5분에 정리
- 이번 달 매출 목표 달성 여부와 원인 판단
- 분기별 병원 전략 회의 자료 준비

### 이 앱이 하지 않는 것

마이브레인은 회계 프로그램·EMR·환자 CRM을 대체하지 않습니다:
- 세무 신고·손익 계산서 발행은 회계사·회계 SW의 영역
- 예약·진료 기록·차팅은 EMR에 그대로 남습니다
- 개별 환자 문자·리마인더는 EMR 또는 카카오 CRM으로

## 2장. 어떤 원장님을 위한 도구인가

- **직군**: 치과 원장 (병원장·개원의)
- **연차**: 개원 3~7년차 안정기~성숙기 진입 시기
- **규모**: 체어 4~10대 · 스태프 6~12명
- **경영에 쓰실 수 있는 시간**: 하루 15~30분

특히 아래 세 가지 질문에 대한 답을 자주 찾고 계시는 원장님께 잘
맞습니다:

1. **위기 감지** — 지금 새고 있는 돈은 어디인가
2. **다음 액션** — 오늘·이번 주 뭘 해야 하나
3. **추세 판단** — 이번 달·분기 흐름은 좋아지고 있는가

이 세 답을 3~5분 안에 얻으실 수 있게 화면을 설계했습니다.

## 3장. 시작하기 전에 준비할 것

### 필수 · 가장 먼저
- **웹 브라우저**: Chrome, Safari, Edge 최신 버전. 스마트폰·태블릿·PC
  모두에서 동일하게 열립니다.
- **인터넷 연결**: 대시보드는 앱을 처음 불러올 때만 인터넷이 필요합니다
  (한번 열어두면 오프라인에서도 부분 사용 가능).

### 있으면 좋음
- **아이디·비밀번호 준비**: 4자 이상 아이디 + 6자 이상 비밀번호
- **병원 이름**: 앱 곳곳에 표시됩니다
- **개원 연차**: 판정 기준을 개인화할 때 사용됩니다 (기본 3년으로 설정)

### 나중에 필요
- **EMR 브랜드**: 두번에·덴트웹·이지플러스 등 (Quest 1에서 선택)
- **원장님의 진료 스타일**: 슬라이더 3개로 정의 (Quest 2에서 조정)
- **재무 서류 3장**: 손익계산서·CAPS 카드 승인 CSV·기타 (Quest 3용)

이 세 가지는 지금 없어도 앱을 시작하실 수 있습니다. Quest 3단계에서
차례로 안내해 드립니다.

## 4장. 화면 언어와 기호 · 색상 안내

앱 전체에서 반복되는 시각 언어를 미리 익혀두시면 훨씬 빨리 읽으실 수
있습니다.

### 색상의 의미
- 🔵 **파랑 (#33A6FF)**: 정상 · 강조 · 클릭할 수 있는 것
- 🟢 **초록 (#00C853)**: 최우수 · 좋은 신호 · 개선 효과
- 🟠 **주황 (#FFB300)**: 경고 · 개선 필요 · 주의
- 🔴 **빨강 (#FF3B30)**: 위기 · 즉시 대응 · 처방 필요
- 🟣 **보라 (#8B5CF6)**: 부가 안내 · 참고 정보
- 딥 네이비 (#00153D): 제목 · 브랜드 · 강한 텍스트

### 반복되는 아이콘
- ⚡ 즉시 실행 · 액션 버튼
- 📈 추세 · 시간별 흐름
- 🎯 정상 범위 (도움말)
- ⚠️ 경고 · 주의
- 🚨 위기 · 처방 필요
- ℹ️ 참고 정보 · 안내
- ✓ 완료 · 체크
- ← / → 뒤로가기 · 다음

### 배지의 뜻
- **최우수 / 우수** = 업계 최상위 그룹 진입
- **정상 / 안정** = 안전 구간 · 유지 관리
- **경고 / 개선 필요** = 3~4주 안에 손대야 함
- **위기 / 즉시 대응** = 오늘·이번 주 액션 필수

### 폰트 크기의 뜻
- 큰 숫자 (24pt~) = 지금 원장님이 주목해야 할 핵심 숫자
- 중간 (15pt) = 본문 · 설명
- 작은 (11pt 이하) = 라벨 · 부가 정보

이 규칙만 알아두시면 어느 화면을 여셔도 3초 만에 "지금 뭐가 중요한가"를
읽어내실 수 있습니다.

# 2부. 처음 사용하기

## 5장. 앱 접속 · 회원가입 · 로그인

### 첫 접속

배포된 URL에 브라우저로 접속하시면 로고 애니메이션이 잠깐 뜨고
회원가입 화면으로 이동합니다.

### 회원가입 화면

세 가지 방법 중 하나를 선택하실 수 있습니다:

**① 아이디로 회원가입 (권장)**
- 아이디 4자 이상 · 비밀번호 6자 이상
- "무료로 시작하기 →" 버튼 tap
- 이후 관제탑 3단계 (Quest)로 진입

**② 소셜 로그인 (Apple·Google)**
- 각각 별도 버튼 tap
- 현재는 시각적 mock (실 인증 미연결) · 향후 실 OAuth 예정

**③ 데모 체험 (제일 아래)**
- "데모 대시보드 바로 체험하기" 버튼
- 회원가입·Quest 없이 바로 대시보드 진입
- 마이브레인 전체 화면을 미리 둘러보고 싶으실 때

### 로그인 화면

이미 계정이 있으신 원장님은 회원가입 화면 하단의 "이미 계정이 있으신가요?
로그인" 링크로 이동하실 수 있습니다.

- 아이디 + 비밀번호 입력 → "로그인" tap
- 로그인 성공 시 대시보드로 자동 이동 (Quest 3단계 미완료면 Quest로)

### 로그인 유지

- 한 번 로그인하시면 브라우저를 닫으셨다 다시 여셔도 자동 로그인됩니다
- 로그아웃은 설정 화면에서 명시적으로 하실 수 있습니다
- 다른 브라우저·기기에서는 별도 로그인이 필요합니다 (세션이 브라우저별)

## 6장. 데모로 먼저 체험하기

데모 진입 방법:
1. 회원가입 화면 맨 아래 "미리보기" 구분선 밑
2. "데모 대시보드 바로 체험하기" 초록 버튼 tap

### 데모에서 보실 수 있는 것

- 서울나눔치과의원 · 박지연 원장 페르소나 (3년차 · 체어 6대 · 스태프 8명)
- 실제 mock 데이터로 채워진 대시보드
- 크리시스 top3 · 처방 모달 · 재무 심층 3섹션
- 히스토리·설정·도움말 등 모든 부속 화면
- NPS 설문 폼

### 데모 vs 실계정 차이

| | 데모 | 실계정 |
|---|---|---|
| 회원가입 | 없음 | 아이디/비밀번호 |
| Quest 3단계 | 건너뜀 | 완료 필수 |
| 원장 성향 | 기본값 | 슬라이더 조정 |
| 데이터 | mock 그대로 | mock (향후 실 EMR) |
| 저장 | 브라우저 로컬 | 브라우저 로컬 |

**데모 → 실계정 전환**: 데모 사용 중 오른쪽 상단 설정 → 로그아웃 후 회원
가입 진행하시면 됩니다.

## 7장. 관제탑 3단계 (온보딩)

회원가입 후 자동 진입하는 화면. 3단계 카드가 세로로 놓여 있습니다.

### Quest 1 · EMR 연결

**무엇을 하는 단계인가**: 병원에서 쓰시는 EMR을 앱에 알려주고 연결
시늉을 하는 단계 (현재는 mock).

- EMR 브랜드 선택 · 예: 두번에, 덴트웹, 이지플러스
- "연결" 버튼 tap
- 초록 배지 · Quest 1 완료

**실 EMR 연동은 언제?**: 향후 API 개방 병원부터 순차 연동. 현재는
mockData 기반 시연.

### Quest 2 · 원장 동기화

**무엇을 하는 단계인가**: 원장님의 진료 스타일·경영 성향을 앱에 알려주는
단계. 이 값들이 나중에 KPI 벤치마크를 개인화하는 데 쓰입니다.

**슬라이더 3개**:

1. **진료 속도**
   - 왼쪽 = 케이스당 시간 여유 · 오른쪽 = 빠른 회전
   - 이 값은 시간당 생산성·체어 회전율 판정에 반영

2. **커뮤니케이션 스타일**
   - 왼쪽 = 핵심 간결 상담 · 오른쪽 = 정서 교감 긴 상담
   - 상담 동의율 목표에 반영 (긴 상담 → 75% 목표 · 짧은 상담 → 65%)

3. **체어 운영 스타일**
   - 왼쪽 = 다수 체어 동시 · 오른쪽 = 소수 집중
   - 노쇼·당일 취소 임계값에 반영 (다수 동시 → 3% 엄격 · 소수 집중 → 5% 허용)

**경영 성향 A/B**:

- **A 타입 · 공격적 확장 (마케팅형 매출 방어)**
  - 인건비 27%까지 허용 (인력에 투자)
  - 미수금 2%까지 허용 (매출 회수보다 매출 확대 우선)

- **B 타입 · 고정비 절감 (내실 리콜 중심)**
  - 인건비 22%로 엄격 (내실 관리)
  - 미수금 1%로 엄격 (현금 흐름 우선)

**어느 쪽을 선택할까**: 정답은 없습니다. 원장님의 지난 3년간 실제 운영
성향에 가까운 쪽을 선택해 주세요. 나중에 설정 화면에서 언제든 재조정
가능합니다.

**완료 방법**: 슬라이더 3개 조정 + A/B 선택 후 하단 "완료" 버튼 tap.

### Quest 3 · 재무 서류 스캔

**무엇을 하는 단계인가**: 재무 데이터를 앱에 넘기는 단계 (현재는 mock).

- 3장의 서류 카테고리:
  1. **일일 리시트** (매일 저녁 · 카드 매출 요약)
  2. **손익 계산서** (월 1회 · 회계사에게 받음)
  3. **CAPS 카드 승인 CSV** (매주 · 카드사에서 다운로드)
- 각 카테고리에서 "문서 선택" tap → 파일 선택 → progress bar → 완료 배지
- **현재는 파싱 없음** (시연 목적). 향후 OCR·CSV 자동 파싱 예정.

### 3단계 완료 후

- 세 개 모두 초록 배지 → `allQuestsCompleted = true`
- 대시보드로 자동 이동
- Quest는 완료 상태로 저장되어 다음부터는 로그인 후 바로 대시보드로 진입

**중간에 그만두면?**: 완료된 단계는 저장됩니다. 다음 로그인 시 Quest
화면으로 진입하되 이미 완료된 카드는 체크된 상태로 표시됩니다.

### 상단 헤더 세부

- 인사말: "안녕하세요, 박지연 원장님"

- 우측 아이콘 3개 (좌→우):
  - 📅 **일일 리시트** (수납 매출 CSV 업로드)
  - 📊 **히스토리** (6개월 KPI 추세)

### HomeFab (다른 화면에서 대시보드로 돌아오기)

- 대시보드가 아닌 모든 화면 (히스토리·설정·도움말 등) 우하단에 있는
  둥근 파랑 버튼
- 눌리면 진동 (모바일) + 대시보드로 즉시 이동
- 인증 전 화면·공개 설문 화면에는 없음

## 9장. 기간 필터: 오늘 · 이번 주 · 이번 달 · 분기

대시보드의 **가장 강력한 컨트롤**. 이 하나의 값이 모든 데이터를 바꿉니다.

### 각 기간의 뜻

- **오늘 (today)**: 지금 시점의 하루 스냅샷 · 즉시 대응
- **이번 주 (week)**: 이번 주 월요일부터의 누적 · 흐름 감지
- **이번 달 (month)**: 이번 달 1일부터 · **기본값** · 가장 자주 보시는 뷰
- **분기 (quarter)**: 최근 3개월 누적 · 전략 판정

### 필터를 바꾸면 무엇이 바뀌는가

거의 모든 것이 바뀝니다:
- HR 관제의 매출·급여·이직 숫자
- 크리시스 top3의 KPI 값과 순위
- 재무 심층의 3축 스코어 · 인사이트 · 처방
- 20 KPI 전체 목록의 각 값과 상태

### 언제 어느 필터를 쓰는가

| 상황 | 추천 필터 |
|---|---|
| 아침 첫 확인 | 오늘 |
| 스태프 미팅 전 | 이번 주 |
| 매출 목표 점검 | 이번 달 (기본) |
| 분기 회의 준비 | 분기 |
| 위기 지표 즉시 대응 | 오늘 → 이번 주 순으로 |

### 실전 팁

- 오전엔 "오늘"로 시작 → 이슈 감지 → "이번 주"로 확대 확인 → "이번 달"로
  구조적 문제 여부 판단
- 필터를 바꿔가면서 처방문의 시간 언어가 함께 바뀌는지 확인 (예: "지금"
  → "이번 분기 안")

## 10장. HR 관제 (좌측 · 매출·급여·스태프)

### 표시되는 정보

**상단 요약**
- 이번 기간 매출 (예: 이번 달 7,850만 원)
- 이번 기간 급여 총액 (예: 이번 달 2,780만 원)
- 급여 비율 (예: 35.4% · 초록/주황/빨강 컬러)

**중단 시각화**
- 주간·일간 매출·급여 세로 바 차트
- 매출·급여를 나란히 놓아 격차 확인 가능

**하단 스태프 리스트**
- 스태프 이름 + 직군 + 근무 상태
- 연속 근무일 · 초과근무 시간 표시
- 번아웃 리스크 있는 스태프는 붉은 표시

### 어떻게 읽는가

**정상 신호**
- 급여 비율 25~30% 사이 · 초록 or 파랑
- 스태프 전원 근무 상태 안정

**경고 신호**
- 급여 비율 30% 초과 · 주황
- 특정 스태프가 7일 연속 근무 (번아웃 임박)
- 목요일 오후 등 특정 시간대에 초과근무 집중

**대응**
- 급여 초과 → 스케줄 재배정 (오후 예약을 오전으로 분산)
- 번아웃 → 다음 날 즉시 휴무 배정
- 초과근무 집중 → 파트 위생사·수당 검토

## 11장. 크리시스 TOP3 · 추가 위기 (중앙)

### TOP3의 의미

이번 기간(period)에 가장 위험한 KPI 3개를 자동으로 뽑아 순위로 표시.

각 카드에는:
- 순위 배지 (🚨 1위 · 2위 · 3위)
- KPI 이름 (예: "인건비 초과")
- 현재 값 (큰 빨강 숫자)
- 벤치마크 대비 격차 (예: "-5%p")
- 임팩트 요약 (예: "이달 손실 확정 380만 원")

### 추가 위기 카드

TOP3 아래에 2개 더:
- **당일 취소율** (cancelRate)
- **미수금 비율** (uncollected)

이 두 지표는 매출·현금 흐름에 직접 타격이라 별도로 상시 감시.

### 카드를 눌렀을 때

각 카드는 tap하면 **처방 모달**이 뜹니다 (14장 참조). 카드 우측 chevron
아이콘 (>)이 tap 가능을 표시.

### TOP3가 매번 다르게 나오는 이유

TOP3는 하드코딩된 목록이 아니라 지금 상태에서 자동으로 뽑힌 것:
- 20 KPI 중 crisis·warning 상태인 것을 모두 수집
- 상태·격차·임팩트 종합해 순위 결정
- period가 바뀌면 TOP3도 바뀔 수 있음

## 12장. 재무 심층분석 (세로 스크롤)

20 KPI로 통합 분석합니다.

### 종합 진단 헤더 (최상단)

- 3축 스코어 배지 (수익성·유지·리스크 각각 0~100 점수)

- rootCause (지금 손대야 할 원인 지표)

### 섹션 1 · 수익성 (Unit Economics)

**무엇을 보는가**: 얼마나 벌고 얼마나 남기는가

**무엇을 보는가**: 지금 새고 있는 돈이 있는가

- InsightCard (주황 톤)
- **노쇼·당일 취소 라인 차트 (AxisTrendLine)**: 시간별 흐름 + 벤치마크 선

## 13장. 종합 진단 헤더 (3축 스코어)

### 3축의 의미

- **수익성** (Profitability · Unit Economics)
- **유지 경제학** (Retention Economics · NRR·VBC)
- **리스크·현금** (Risk · Lean·Cash Flow)

각 축 스코어는 0~100. 그 축에 속한 KPI들의 상태를 가중 평균한 값.

### 밴드

- **최우수 (excellent, 75+)** — 성장 시그널
- **정상 (healthy, 50~75)** — 유지 관리
- **개선 필요 (risk, 30~50)** — 손대야 함
- **위기 (critical, <30)** — 즉시 재구조화

### 3축 조합의 해석

원장님이 자주 만나는 조합과 그 뜻:

| 수익성 | 유지 | 리스크 | 지금 상황 | 다음 액션 |
|:---:|:---:|:---:|:---|:---|
| 67 | 50 | 60 | 벌고 있지만 유지가 약함 | 리콜·재내원부터 |
| 45 | 75 | 50 | 환자 유지는 강한데 밀도 낮음 | 케이스 믹스 개선 |
| 60 | 60 | 30 | 벌고 유지도 되는데 현금 샘 | 미수금·취소·이직 즉시 |
| 30 | 40 | 20 | 3개 축 모두 흔들림 | 구조적 재편 필요 |

### 근본 원인 (rootCause)

3축 스코어만으로는 "어느 KPI를 손대야 하는가"가 안 나옵니다. 그래서 앱이
자동으로 하나의 상류 원인 지표를 지목:

예: 위기 상태인 KPI가 patientLtv·preventiveRecall·marketingROI 3개일 때
→ 이 셋의 공통 원인은 recallRate → **rootCause = recallRate** 로 지목.

### (?) 아이콘 tap → 스코어 설명 모달

- 각 축이 왜 이 점수인지
- 어떤 KPI들이 기여하는지
- Tier S 가중치 (2× 가중되는 5개 지표) 설명
- 밴드별 의미
- 쉬운말로 정리

## 14장. KPI 카드를 눌렀을 때 뜨는 처방 모달

크리시스 top3·추가 위기·재무 심층 KPI 카드·20 KPI 확장 목록 어느 카드든
tap 하시면 처방 모달이 아래에서 올라옵니다.

### 모달 구조

**상단 헤더**
- 🚨 위기 처방전 배지
- KPI 이름 (예: "인건비 초과")
- 현재 값 (큰 숫자 + 단위)

**분석 내용 (빨강 도트 bullet)**
- 왜 이 값이 이 상태인지 3~4개 항목
- 마지막 항목: **쉬운말 풀이** (원장님 언어로 요약)

**해결 방안 (파랑 도트 bullet)**
- ① 오늘 · ② 이번 주 · ③ 이번 달 (또는 분기) 3단 액션
- 실장님·스태프에게 지시할 수 있는 형태

**기대 효과 (초록 도트 bullet)**
- 각 액션이 가져올 금전적·구조적 효과
- 예: "리마인드 문자 발송 시 노쇼율 -3~4%p 감소 확인됨"

**즉시 실행 CTA (빨강 버튼)**
- 한 문장의 즉시 액션 (예: "내일 예약자 리마인드 지금 발송")
- 이 버튼은 현재 시각적 표시 · 실제 알림 발송은 향후 EMR 연동 후

### 처방 읽기 팁

1. **먼저 (풀이) 문단만 읽기** — 원장님 언어로 요약된 마지막 bullet
2. **동의되면 해결 방안 3단 읽기** — 오늘/이번 주/이번 달 액션
3. **기대 효과로 결정 확신** — 얼마의 매출이 회복되는가
4. **실장님에게 전달** — 캡처 or 요약해서 미팅에서 논의

### 결과 지표 vs 원인 지표

처방문이 "이 지표를 직접 손대지 말고 상류 지표부터 개선하세요"라고
말하는 경우가 있습니다. 예:
- **patientLtv (환자 LTV)** = 결과 → 리콜 성공률·재내원율 먼저
- **ltvCac (LTV:CAC)** = 결과 → LTV 개선 먼저
- **marketingROI** = 결과 → 상류 LTV·리콜부터

이런 지표는 아무리 목표를 세워도 직접 손댈 방법이 없습니다. 상류를
개선하면 자동으로 함께 올라옵니다.

### Period 스코프

- 처방 텍스트가 원장님이 선택한 기간에 맞춰 나옵니다
- 오늘: "지금 오후에" 언어
- 이번 주: "이번 주 남은 예약자에게"
- 이번 달: "오늘 · 이번 주 · 다음 달" 3단
- 분기: "이번 분기 안에 · 다음 분기"

## 15장. 히스토리 (6개월 추세)

### 진입 경로
- 대시보드 상단 우측 📊 아이콘 tap
- 또는 다른 화면에서 HomeFab → 대시보드 → 히스토리

### 무엇을 볼 수 있는가

- **20개 KPI 전체의 6개월 추세**
- 각 KPI 카드에:
  - 6개월 라인 차트 (min-max 스케일)
  - 최근 값 · 지난 값 대비 변화
  - **결과 배지**: 개선 (초록) · 악화 (빨강) · 유지 (회색)
  - **판정 타입 배지**: ABS · REL · DERIVED
  - **benefitDirection 화살표**: 이 지표는 올라가야 좋은가 (↑) · 내려가야 좋은가 (↓) · 유지가 좋은가 (=)

# 6부. NPS 설문 운영

## 23장. NPS가 무엇이며 왜 보는가

### NPS(Net Promoter Score)란

환자에게 "이 병원을 지인에게 추천하시겠어요?"를 0~10점 척도로 물어서
계산하는 만족도 지수.

- **9~10점**: 추천자 (Promoter)
- **7~8점**: 중립자 (Passive)
- **0~6점**: 비추천자 (Detractor)

**NPS = %추천자 - %비추천자** (즉 -100 ~ +100 사이 값)

### 왜 중요한가

- 절대 점수보다 **추세**가 중요 (오르는 방향인지)
- 60점 이상 = 입소문 성장 임계점 (소개 환자 급증)
- 70점 이상 = 자연 성장 엔진 가동 (마케팅비 절감 시작)
- 소개로 오는 환자는 LTV가 광고로 오는 환자의 1.6배

### 원장님 병원의 활용

마이브레인은 NPS 수집·저장·요약·내보내기 전체를 지원합니다. 태블릿에서
받은 응답을 원장 앱으로 옮겨 요약을 확인하실 수 있습니다.

## 25장. QR 코드 인쇄 · 벽에 붙이기

태블릿을 상시 두기 어려운 경우, QR 코드로 환자가 자기 스마트폰으로
바로 접근하도록 하실 수 있습니다.

### QR 코드 얻는 방법

1. 원장님 앱 → 도움말 → NPS 섹션 아래로 스크롤
2. **NpsExportCard** 카드에 QR 코드가 자동 표시됨
3. QR 코드 이미지를 스크린샷
4. 인쇄 (A5 or A6 크기 권장)

### 붙이는 위치

- 대기실 벽 (환자 시선 높이)
- 수납 데스크
- 화장실 문 (짧은 대기 시간 활용)
- 상담실 안내판

### 옆에 붙일 안내 문구 예시

> "치료는 어떠셨나요?
>  1분만 시간 내주시면 큰 도움이 됩니다.
>  QR 스캔 → 만족도 체크
>  익명입니다."

### QR이 스캔 안 될 때

- QR 이미지가 너무 작음 (5cm × 5cm 이상 권장)
- 인쇄가 흐릿함 (선명하게 다시 인쇄)
- 환자 폰의 카메라 앱이 QR 인식 안 함 (일부 구형 폰) → 태블릿 병용

## 26장. 응답 CSV로 내보내고 원장 앱에 불러오기

태블릿·환자 스마트폰에서 저장된 응답을 원장 앱으로 모으는 과정.

### 왜 CSV 교환인가

- 지금은 백엔드 서버 없음 · 각 브라우저에 로컬 저장
- 백엔드 없이도 실 병원에서 시연·운영 가능하도록 CSV 폴백 마련
- 향후 백엔드 붙으면 자동 동기화 (원장님이 아무것도 안 해도 됨)

### 태블릿에서 내보내기

1. 태블릿 브라우저에서 `/survey`가 아니라 도움말 (설정 → 도움말) 진입이
   필요 → 태블릿용 별도 계정 만들거나 원장 계정으로 로그인
2. 도움말 → NPS 섹션 → NpsExportCard 열기
3. "CSV 내보내기" 버튼 tap
4. 브라우저가 CSV 파일 다운로드
5. 이 파일을 원장 앱 기기로 전송 (이메일·에어드롭·카카오톡 파일)

**주의**: 공개 `/survey` URL은 응답 입력만 · 관리자용 도구는 없습니다.
태블릿을 관리자 계정으로 로그인해두거나, 정기적으로 원장님이 그 태블릿에
서 직접 CSV를 뽑아야 합니다.

### 원장 앱에 불러오기

1. 원장 앱 → 도움말 → NPS 섹션 → NpsExportCard
2. "CSV 불러오기" 버튼 tap
3. 기기에서 CSV 파일 선택
4. 자동으로 응답 병합 (id 중복은 스킵)
5. 결과 요약: "added: 12 · skipped: 3"

### 병합 후 확인

- NPS 요약 카드에 응답 수 · 평균 · NPS 점수 갱신
- 최근 응답 목록에 새 응답이 나타남
- 어떤 태블릿(tabletId)에서 왔는지 표시됨

## 27장. NPS 요약 읽는 법

### 요약 카드에 표시되는 값

- **NPS 점수** (예: 51) — %추천자 - %비추천자
- **총 응답 수** (예: 87)
- **평균 점수** (예: 8.4)
- **추천자·중립자·비추천자 비율** (예: 62% · 27% · 11%)
- **월별 추세** (예: 42 → 45 → 41 → 48 → 51)

### 어떻게 읽는가

**정상 신호**
- 3개월 연속 상승 (예: 42 → 45 → 48)
- 비추천자 비율 15% 이하

**경고 신호**
- 3개월 연속 하락
- 특정 응답에 심각한 서술 반복 등장

**대응**
- 낮은 점수(0~6점) 응답자에 원장 직접 팔로업 전화
- 이유 서술에서 반복 등장하는 키워드 찾기 (대기시간·비용·상담)
- 이번 주 · 이번 달 개선 계획 수립

### 실전 활용

- **월 1회 검토** 권장 (매월 첫 주)
- 응답이 20건 미만이면 통계적 의미 낮음 · 수집 강화
- 60점 넘으면 소개 환자 증가 확인 (히스토리에서 newPatients 추이)

# 7부. 원장 성향 조정

## 28장. 슬라이더 3개의 의미

Quest 2 또는 설정 화면에서 조정 가능한 3개 슬라이더는 원장님의 실제
진료·경영 스타일을 앱에 알려주는 도구입니다.

### 슬라이더 1 · 진료 속도

- **왼쪽 (0)**: 케이스당 시간 여유
  - 상담·설명·라포 형성에 시간 투자
  - 시간당 매출은 낮지만 만족도·재내원 강함
- **오른쪽 (1)**: 빠른 회전
  - 케이스당 시간 최소화
  - 시간당 매출 높지만 만족도·재내원 부담

**이 값이 반영되는 곳**: 시간당 생산성 목표 · 체어 회전 벤치마크

### 슬라이더 2 · 커뮤니케이션 스타일

- **왼쪽 (0)**: 핵심 간결 상담 (5~10분)
  - 필요한 정보만 전달 · 시간 효율 강함
- **오른쪽 (1)**: 정서 교감 긴 상담 (15~25분)
  - 환자와 관계 구축 · 상담 동의율·리콜 강함

**이 값이 반영되는 곳**: 상담 동의율 목표 (긴 상담 → 75% · 짧은 상담 → 65%)

### 슬라이더 3 · 체어 운영 스타일

- **왼쪽 (0)**: 다수 체어 동시 (원장 + 위생사 병렬 진료)
  - 처리량 최대 · 빈 체어 리스크 큼 (노쇼·취소 타격 큼)
- **오른쪽 (1)**: 소수 체어 집중 (원장 하나에 집중)
  - 처리량 낮음 · 빈 체어 리스크 낮음

**이 값이 반영되는 곳**: 노쇼·당일 취소 임계값 (다수 동시 → 3% 엄격 · 소수 집중 → 5% 허용)

### 언제 재조정하는가

- 처음 Quest 2에서 설정 (개원 3~5년차 원장님의 안정 성향으로)
- 병원 확장 (스태프·체어 증설) 시 재조정
- 원장님 진료 방식이 바뀔 때 (예: 라포 중심 → 처리량 중심)
- 계절적 캠페인 (여름 방학 특수 등) 대응 시 임시 조정

## 29장. A형 vs B형 경영 성향

### A 타입 · 공격적 확장 (마케팅형 매출 방어)

**어떤 원장님인가**
- 개원 초기·중기 · 성장 우선
- 인력·마케팅에 적극 투자
- 매출 상단을 뚫는 게 우선

**앱에 미치는 영향**
- 인건비 27%까지 허용 (스태프 확장·수당 여유)
- 미수금 2%까지 허용 (매출 회수보다 매출 확대 우선)
- 처방문의 액션이 "확장·투자·마케팅 증액" 톤

### B 타입 · 고정비 절감 (내실 리콜 중심)

**어떤 원장님인가**
- 개원 안정기·성숙기 · 내실 우선
- 스태프 안정·재내원·리콜 강화
- 지속 가능한 수익률 방어

**앱에 미치는 영향**
- 인건비 22%로 엄격 (효율 극대화)
- 미수금 1%로 엄격 (현금 흐름 우선)
- 처방문의 액션이 "리콜·재내원·SOP 표준화" 톤

### A/B 선택 안 함 (기본)

- 인건비 25% · 미수금 1.5% 중간값
- 어느 방향으로도 편향 없음
- 어느 성향인지 아직 결정 안 됐거나 균형 원하시는 원장님용

### 재선택 방법

- 설정 화면 → 경영 성향 카드 tap → 다른 타입 선택 · 또는 같은 타입 tap하면 해제
- 즉시 저장 · 대시보드로 돌아가면 벤치마크가 새 성향으로 조정됨

## 30장. 이 값이 벤치마크에 어떻게 영향을 주는가

### 벤치마크 개인화 흐름

```
원장 성향 (슬라이더 3 + A/B)
    ↓
getAdjustedBenchmarks(성향)
    ↓
개인화된 임계값 (예: 인건비 27% · 노쇼 3%)
    ↓
KPI 판정에 반영
    ↓
크리시스 top3 · 3축 스코어 · 처방 텍스트 조정
```

### 예시 · A형 원장님 vs B형 원장님

같은 인건비 26%가 나왔을 때:
- **A형**: 27% 안 · 정상 판정 · 처방 없음
- **B형**: 22% 초과 · 위기 판정 · 즉시 대응 처방
- **기본**: 25% 초과 · 경고 판정 · 이번 달 개선 처방

### 왜 이렇게 개인화하는가

- 절대 목표 강요는 오판을 낳음 (신규 병원은 위기로 · 성숙기는 안일)
- 성숙기·안정기·확장기 각각 다른 지표 프로파일
- 원장님이 "왜 남의 병원 기준으로 판정받아야 하나" 느끼지 않도록

### 개인화 범위

지금은 인건비 · 노쇼 · 당일 취소 · 상담 동의율 · 미수금 5개 KPI가 성향
에 따라 조정됨. 향후 다른 지표들도 확대 예정.

# 8부. 20 KPI 완전 이해

각 KPI의 뜻·정상 범위·왜 중요한가를 정리합니다. 도움말 용어사전과 상보
관계 · 여기서는 원장님이 실전에서 어떻게 활용하는가에 초점.

## 31장. 매출·수익성 지표 5개

### 1. 월 매출 (Monthly Revenue)
- **뜻**: 그 기간(월 or 주 or 일) 병원이 벌어들인 총 진료비 (보험 + 비급여)
- **정상 범위**: 절대값 없음 · 연차·체어 대비 REL 판정 (개원 3년차·체어 6대 안정권은 월 7,000~8,500만 원)
- **왜 중요**: 병원 규모의 절대적 척도 · 3개월 연속 상승 여부가 진짜 신호

### 2. 월 순이익률 (Net Profit Rate)
- **뜻**: 매출 - 모든 비용(인건비·재료비·기공료·임대료·세금) → 남는 돈의 비율
- **정상 범위**: 개원 초기 10% · 안정기 20~25% · 성숙기 25~30%
- **왜 중요**: 최종 척도 · 원장님 통장에 실제로 얼마 남는가

### 3. 환자 LTV (Lifetime Value)
- **뜻**: 환자 한 명이 병원을 다니는 전체 기간 지불 총액
- **계산**: 객단가 × 연간 내원 횟수 × 평균 유지 연수
- **정상 범위**: 우수 ≥280만 원 · 정상 200~280 · 위기 <140만 원
- **왜 중요**: 마케팅 회수 · 결과 지표 (직접 손대지 말고 상류부터)

### 4. LTV:CAC 비율
- **뜻**: 환자 LTV ÷ 유치 비용
- **정상 범위**: 3~5배 정상 · <2배 광고비 손해 · >5배 광고 확장 여력
- **왜 중요**: 마케팅 효율 · 결과 지표

### 5. 시간당 생산성 (Hourly Productivity)
- **뜻**: 체어 한 대가 1시간 돌 때 벌어들이는 진료비
- **정상 범위**: 시간당 고정비의 2배 이상 (예: 고정비 18만/h → 목표 36만/h)
- **왜 중요**: ToC 병목 지표 · 체어·케이스 믹스 개선의 결과

---

## 32장. 환자·예약 지표 10개

### 6. 체어 가동률 (Chair Utilization)
- **뜻**: 진료실 의자가 열려있는 시간 중 실제 진료 시간 비율
- **정상 범위**: 70~85% 최적 · <70% 매출 손실 · >90% 번아웃 임박
- **왜 중요**: ToC의 핵심 병목 자원 · 매출 상한 결정

### 7. 예약 충족률 (Appointment Rate)
- **뜻**: 예약 가능 슬롯 중 실제 예약된 비율
- **정상 범위**: ≥95% 우수 · 90~95 정상 · <85% 위기
- **왜 중요**: 스태프·체어 놀리지 않는지

### 8. 당일 취소율 (Cancel Rate)
- **뜻**: 예약 100건 중 당일에 취소된 비율
- **정상 범위**: ≤3% 우수 · 3~5% 경고 · >5% 위기
- **왜 중요**: 체어 90분 공백 + 평균 13만 원 손실/건

### 9. 노쇼율 (No-Show)
- **뜻**: 예약해놓고 연락 없이 안 온 환자 비율
- **정상 범위**: ≤4% 정상 · >5% 경고 · >6% 위기
- **왜 중요**: 체어 50분 공백 + 평균 23만 원 손실/건

### 10. 신환 내원 (New Patients)
- **뜻**: 그 기간 처음 온 환자 수 (+ 전체 대비 비중)
- **정상 범위**: 신환 비중 15~25% · 부족하면 마케팅 부족 · 초과면 재내원 약함
- **왜 중요**: 성장 엔진 · 자연 유입 대비 광고 비중

### 11. 재내원율 (Return Rate)
- **뜻**: 치료 끝난 환자가 다시 병원을 찾은 비율
- **정상 범위**: >70% 우수 · 55~70% 정상 · <40% 위기 (v0.4 정정)
- **왜 중요**: 유지 경제학의 정점 · 광고 없이 벌 수 있는 매출의 근간

### 12. 리콜 성공률 (Recall Rate)
- **뜻**: 정기 검진 안내 환자 중 실제로 예약 잡은 비율
- **정상 범위**: ≥75% 우수 · 60~75% 정상 · <45% 위기
- **왜 중요**: 재내원율·환자 LTV의 상류 원인 · 자동화만 해도 40% 개선

### 13. 진료 완료율 (Treatment Complete)
- **뜻**: 계획한 치료를 중도 이탈 없이 마친 환자 비율
- **정상 범위**: ≥85% 최상위 · ≥75% 정상 · <60% 위기
- **왜 중요**: 미완료 원인 1위는 비용 부담 · 분납 옵션으로 즉시 개선

### 14. 상담 동의율 (Case Acceptance)
- **뜻**: 상담 후 실제로 치료 계약으로 이어진 비율
- **정상 범위**: ≥70% 우수 · 60~70 정상 · <50% 위기 (커뮤니케이션 슬라이더에 따라 조정)
- **왜 중요**: 매출 성장의 가장 빠른 레버

### 15. 환자 NPS (Net Promoter Score)
- **뜻**: 추천 점수 · 3개월 추세 판정
- **정상 범위**: 3개월 연속 상승 = 정상 · 60점+ 입소문 임계 · 70점+ 자연 성장
- **왜 중요**: 소개 환자 · 마케팅비 절감

---

## 33장. 비용·인력 지표 8개

### 16. 인건비 비율 (Labor Cost Ratio)
- **뜻**: 매출 대비 전체 인건비
- **정상 범위**: ≤25% 우수 · 25~30% 정상 · >35% 위기 (A형 27% / B형 22% 조정)
- **왜 중요**: 순이익률 급감의 주범 · 초과분은 확정 손실

### 17. 재료비 비율 (Material Cost)
- **뜻**: 매출 대비 진료 재료(임플란트 픽스처·크라운·소모품) 비용
- **정상 범위**: 최상위 <5% · 안정 벤치 5~8% · 위기 >25%
- **왜 중요**: 갑자기 오르면 도매처 재검토 신호

### 18. 기공료 비율 (Lab Fee)
- **뜻**: 보철 매출 대비 외주 기공소 지출 비율
- **정상 범위**: 최상위 <3% · 안정 벤치 3~7% · 위기 >15%
- **왜 중요**: 디지털 덴티스트리 도입 시 자연스레 하락

### 19. 미수금 비율 (Uncollected)
- **뜻**: 매출 중 아직 회수되지 않은 비율
- **정상 범위**: ≤1.5% 우수 · >3% 위기 (A형 2.0% / B형 1.0% 조정)
- **왜 중요**: 60일 초과 시 회수율 급락 · 골든타임 있음

### 20. 스태프 이직률 (Staff Turnover)
- **뜻**: 1년간 그만두는 스태프 비율
- **정상 범위**: <10% 우수 · 10~15% 정상 · >25% 위기
- **왜 중요**: 이직 1명 = 500만 원 손실 (채용+교육+생산성 손실)

### 21. 스태프 생산성 (Staff Productivity)
- **뜻**: 스태프 1인당 창출한 월 매출
- **정상 범위**: 안정 벤치 인당 월 1,000만 원 이상 (8명 규모 기준)
- **왜 중요**: 신규 채용 vs 현 스태프 생산성 강화 판단 기준

### 22. 예방·리콜 매출 비중 (Preventive Recall)
- **뜻**: 전체 매출 중 스케일링·검진·예방 진료 비중
- **정상 범위**: ≥20% 우수 · 12~20% 정상 · <12% 위기
- **왜 중요**: 정기 수익 기반 · 임플란트 편중 리스크 회피

### 23. 마케팅 ROI (Marketing ROI)
- **뜻**: 광고비 1원당 매출 비율
- **정상 범위**: ≥500% 우수 · 300~500 정상 · <200% 위기
- **왜 중요**: 채널별 판정 필요 · 결과 지표 (LTV·리콜부터)

# 9부. 처방 읽고 실행하기

## 34장. 처방 5요소: 분석·해법·효과·액션·풀이

한 개의 KPI 처방 모달은 항상 이 순서로 5요소를 담습니다.

### 1. 분석 내용 (빨강 도트 bullet 3~4개)

**목적**: 이 값이 이 상태인 근거를 보이는 것

- 벤치마크 대비 몇 %p 차이
- 왜 이 상태가 됐는지 (원인 지목)
- 방치 시 손실 추정 (예: "이달 손실 확정 380만 원")
- **마지막 bullet은 쉬운말 풀이** (원장 언어로 위 내용 요약)

### 2. 해결 방안 (파랑 도트 bullet 3개)

**목적**: 무엇을 · 언제 · 어떻게 할 것인가

3단 구조:
- **① 오늘 (또는 지금·이번 주 초)**: 즉시 실행 가능한 액션 하나
- **② 이번 주 (또는 이번 달 초)**: 며칠 내 세팅할 프로세스
- **③ 이번 달 (또는 분기)**: 구조적 개선

각 액션은 원장님이 실장님·스태프에게 지시할 수 있는 형태로 작성됨.

### 3. 기대 효과 (초록 도트 bullet 3개)

**목적**: 각 액션이 가져올 결과

- 즉각적 효과 (예: "리마인드 문자 발송 즉시 노쇼율 -3~4%p")
- 이달·이번 주 회복액 (예: "월 방어액 500만 원")
- 연간·복리 효과 (예: "연간 방어액 6,000만 원 · 유지 경제학 복리 3년 후 2.1배")

### 4. 즉시 실행 CTA (빨강 버튼)

**목적**: 한 문장의 즉시 액션 표시

예: "내일 예약자 리마인드 지금 발송"

**현재는 시각적 · 향후 EMR 연동 후 실 알림 발송으로 승격 예정**

### 5. 풀이 (분석 마지막 bullet)

**목적**: 위의 모든 내용을 원장님 언어로 다시 정리

- 개념 · 왜 이 값이 이런지 · 무엇을 하면 좋은지를 대화체로
- 회계·경영 전문 용어 없음
- 이 하나만 읽어도 처방의 핵심 이해 가능

### 5요소를 어느 순서로 읽는가

**바쁠 때 (30초)**:
1. 풀이만 읽기 (마지막 bullet)
2. 액션 CTA만 확인

**정상 검토 (2분)**:
1. 풀이 → 액션 CTA
2. 해결 방안 3단 확인
3. 기대 효과 · 얼마 회복되는지 확인

**깊은 이해 (5분)**:
1. 분석 내용 전체
2. 풀이로 언어 정리
3. 해결 방안 · 기대 효과
4. 실장님 카톡 or 미팅 안건 메모

## 35장. 처방을 실장님·스태프에게 전달하는 법

### 방법 1 · 카톡 스크린샷 (빠름)

- 처방 모달 캡처
- 실장님에게 카톡: "이거 참고해서 오늘·이번 주 액션 진행해주세요"
- 30초에 끝나는 전달

### 방법 2 · 요약 메시지 (권장)

원장님이 처방을 읽고 병원 상황에 맞게 재작성:

> "인건비 이슈 대응 필요.
>  ① 오늘: 목요일 오후 예약 3건 → 수요일 오전 이동
>  ② 이번 주: 최하늘 위생사 내일 하루 휴무
>  ③ 다음 주: 초과근무 시 파트 위생사 자동 호출 기준 세팅
>  이유: 이달 380만 원 초과분 발생 중 · 방치 시 이달 확정 손실"

- 병원 특정 스태프 이름·요일 등 반영 가능
- 실장님이 즉시 실행 가능한 형태

### 방법 3 · 주간 미팅 안건 (구조적)

- 매주 월요일 미팅에서 지난주 처방 3~5개 리뷰
- 각 처방의 결과 확인 (실행됐는가 · 효과 있었는가)
- 이번 주 새 처방 3~5개 배정

### 방법 4 · 월간 리뷰 (전략)

- 매월 첫 주에 지난달 처방 전체 리뷰
- 반복적으로 나오는 처방은 구조 문제 (예: 매달 인건비 초과 → 인력 재편)
- 실행 안 되고 넘어간 처방은 원장·실장 협의 필요

## 36장. 결과 지표 vs 원인 지표 · 어디부터 손대야 할까

### 결과 지표란

이 값을 직접 손대려 하면 무리한 목표가 되는 지표:
- **환자 LTV** (patientLtv)
- **LTV:CAC 비율** (ltvCac)
- **월 매출** (monthlyRevenue) — 부분적
- **순이익률** (netProfit) — 부분적
- **마케팅 ROI** (marketingROI)
- **스태프 생산성** (staffProductivity)

이 지표들의 처방은 항상 "이 값을 직접 손대지 말고 상류 원인 지표부터
개선하세요"로 시작합니다.

### 원인 지표 (Upstream)

다른 지표에 영향을 주는 상류 지표:
- **리콜 성공률** (recallRate) — 재내원·LTV·예방매출 3개의 상류
- **재내원율** (returnRate) — LTV·마케팅 ROI 상류
- **진료 완료율** (treatComplete) — LTV·NPS 상류
- **체어 가동률** (chairUtil) — 매출·시간당 생산성 상류
- **상담 동의율** (caseAcceptance) — 매출·전환율 상류

이 지표들부터 개선하면 하류 결과 지표가 자동으로 함께 개선.

### rootCause로 우선순위 결정

앱이 자동으로 지목하는 rootCause를 첫 번째 우선순위로 잡으세요:
- 크리시스 top3 · 3축 스코어 헤더에 표시됨
- 이 하나로 여러 개의 하류 위기 지표가 동시에 회복

### 우선순위 체크리스트

1. 종합 진단 헤더에 뜬 rootCause 지표부터
2. 그 다음 crisis 상태인 원인 지표들
3. 결과 지표는 상류 개선 3~4주 후 자동 회복 확인
4. 여전히 회복 안 되면 그때 결과 지표 직접 처방 고려

## 부록 A. 자주 묻는 질문 (FAQ)

### Q. 인증이 안 될 때 어떻게 하나요?
A. 아이디는 4자 이상 · 비밀번호는 6자 이상이어야 합니다. 잊으셨다면
   현재는 재설정 기능이 없어 새 계정 만들기가 유일한 방법입니다 (향후
   비밀번호 재설정 예정).

### Q. 데이터가 다른 기기에서 안 보여요.
A. 현재는 브라우저 로컬 저장 (AsyncStorage) 방식이라 기기별 별개입니다.
   같은 계정으로 로그인해도 데이터는 각 기기에 따로 저장됩니다.
   향후 백엔드 도입 시 자동 동기화 예정.

### Q. Period를 바꿔도 값이 안 바뀌는 것 같아요.
A. 대부분의 값은 즉시 바뀝니다. 만약 특정 카드가 안 바뀌면 새로고침 후
   확인해주세요. 계속 안 바뀌면 문의 채널로 알려주세요.

### Q. 처방을 실행했는데 KPI가 안 좋아져요.
A. 원인이 여러 개일 수 있습니다. rootCause 지표를 먼저 잡아야 하류
   결과가 함께 회복됩니다. 3~4주 안에 개선이 없으면 원인 재검토가 필요.

### Q. 스태프 이름이 왜 우리 병원 스태프가 아닌가요?
A. 현재는 mock 데이터 (박지연 원장·서울나눔치과)입니다. 실 EMR 연동 후
   실제 스태프·환자로 채워집니다.

### Q. 데모 모드에서 저장한 데이터는 어떻게 되나요?
A. 브라우저 로컬 저장이므로 데모에서 회원가입으로 넘어가면 새 세션
   시작됩니다. 데모 데이터는 그대로 있고 새 계정 데이터가 별도로 저장.

### Q. QR 코드가 태블릿과 원장 앱에서 다른가요?
A. QR 자체는 현재 접속한 도메인의 `/survey` URL을 인코딩합니다. 원장 앱
   에서 뜬 QR을 인쇄하면 정확한 URL로 연결됩니다.

### Q. CSV 파일을 어디서 다운로드하나요?
A. 원장 앱 → 도움말 → NPS 섹션 → NpsExportCard의 "CSV 내보내기" 버튼.
   브라우저 다운로드 폴더에 저장됩니다.

### Q. 알림·푸시 기능은 언제 되나요?
A. 향후 EMR 연동과 함께 · 처방 CTA를 실 알림으로 발송하는 시스템 예정.

### Q. 다국어 지원되나요?
A. 현재 한국어만. 영어·일본어 등은 향후 로드맵.

### Q. 다크모드가 되나요?
A. 준비는 되어 있으나 아직 활성화 안 됨. 향후 릴리스 예정.

## 부록 C. 용어 사전 (약식)

앱 안 도움말에 있는 용어사전(23개 KPI + 부속 약어)의 요약. 상세는 앱 내

### 앱 개념
- **관제탑 3단계 (Quest)**: EMR 연결 · 원장 동기화 · 재무 스캔

### 판정 방식
- **ABS (Absolute · 절대 기준)**: 업계 공통 임계값

- **NRR**: Net Revenue Retention · 유지 경제학
- **VBC**: Value-Based Care · Porter · Harvard
- **Lean · TPS**: 7대 낭비 · Toyota
- **ToC**: Theory of Constraints · 병목 · Goldratt
- **LTV**: Lifetime Value · 환자 평생 매출
- **CAC**: Customer Acquisition Cost · 신환 유치 비용
- **NPS**: Net Promoter Score · 만족도
- **BEP**: Break-Even Point · 손익 분기

### 데이터·EMR
- **EMR**: Electronic Medical Record · 진료 기록 시스템

### 로그인 유지 규칙

- **한 번 로그인**하시면 브라우저 종료 후 재접속에도 유지
- **다른 브라우저·기기**에서는 별도 로그인 필요 (세션은 브라우저별)
- **로그아웃 하지 않는 한** 무기한 유지 (일반 웹 앱과 동일)

### 데이터 저장 위치

- 현재는 브라우저의 로컬 저장소 (AsyncStorage · localStorage)
- 각 기기·브라우저별로 별개 저장
- 브라우저 데이터 삭제 시 앱 데이터도 사라짐

### 백업이 필요한 데이터

- NPS 응답 · CSV로 정기 내보내기 권장
- 그 외 mock 데이터는 앱이 자동 생성이라 백업 불필요

### 향후 백엔드 도입 시

- 로그인 → 계정 기반 자동 동기화
- 여러 기기에서 같은 데이터 조회
- 실시간 갱신
- 백엔드 저장으로 브라우저 삭제해도 데이터 유지

### 데이터 삭제 원하시면

- 로그아웃 → defaultState로 초기화 (앱 안에서)
- 브라우저 개인정보 → 사이트 데이터 삭제 (완전 삭제)
- 향후 백엔드 도입 시 계정 삭제 기능 예정
